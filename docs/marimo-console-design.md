# Cadence Console — design notes

A live dashboard view over a Cadence repo, rendered in a [Marimo](https://marimo.io) notebook. Forward-looking work; not yet shipped. This document distills the architectural decisions from the v1.1 design pass so the eventual implementation has a single reference to consult.

The Console is the answer to one question: *"What if my repo had a live face — not the dashboard the SessionStart hook prints, but a real visual surface I could glance at while working?"* The agent writes content into the repo; Marimo cells watch the files and re-render.

## TL;DR

- **"Notebook references, Claude Code owns sidecars."** The `console.py` notebook file is human-authored and stable; every agent-managed section lives in a separate `narratives/console/*.cc.md` file rendered via `mo.watch.file(path).read_text()`. Claude Code only ever writes to the `.cc.md` files, never to `console.py`.
- **Default invocation: `subprocess(["claude", "-p", ...])` (Pattern A).** Simple, no Python deps beyond stdlib, identical to Cadence's existing CLI surface. The SDK path (`claude-agent-sdk`, Pattern B) and the ACP path (Pattern C) are documented as future enhancements.
- **`marimo-check` PostToolUse hook.** Bundled with the plugin so any `.py` notebook edit self-corrects formatting.

## Why this shape

The natural temptation is to interleave agent-managed sections inside `console.py` itself, marked with `<!-- CC:generated start -->` comments. The temptation doesn't survive verification.

Marimo's "Text formatting is preserved" guarantee — documented in `marimo/_tutorials/fileformat.py` — applies inside `@app.cell` function bodies only. The area between cells is regenerated by codegen, and arbitrary top-level comments are not promised to survive a roundtrip (marimo issue #2369 explicitly tracks this as a feature request). A marker comment placed outside an `@app.cell` decorator gets regenerated away on the next save.

The "sidecar" pattern sidesteps this entirely: Claude Code edits markdown files in `narratives/console/`, and small Marimo cells render those files via `mo.watch.file`. The notebook structure is stable; the agent-managed content lives in real files that survive any editing tool. This is the same pattern Eric Ma reaches for in [Use coding agents to write marimo notebooks](https://ericmjl.github.io/blog/2025/10/28/use-coding-agents-to-write-marimo-notebooks) as the "let the agent write Python; let the notebook render results" mental model.

The only thing the sidecar pattern gives up vs. true inline interleaving: Claude Code can't write *Python code* inside the notebook unless it edits `console.py` directly. For Cadence Console that's the right tradeoff — the Python is plumbing; the value is the `.cc.md` content.

## Where the notebook lives

- **Master copy:** `cadence-plugin/views/console.py` in the plugin repo. Versioned with the plugin.
- **Per-repo install:** `/cadence:init` copies it to `<repo>/.cadence/views/console.py` on first run. Users can edit the local copy; future plugin updates do NOT overwrite it. A `cadence:init --update-console` flag re-copies if requested.
- **Launch:** a `/cadence:console` slash command runs `marimo edit --watch .cadence/views/console.py`.
- **Schema sync:** if Cadence's data model evolves, version the schema in `cadence-plugin/cadence-reference.md` and have `cadence:init` detect schema drift via a `.cadence/schema_version` file.

## Notebook layout

Every cell carries a stable function name so cell IDs survive Claude Code edits. Markdown sections render via `mo.watch.file(path).read_text()`, which auto-refreshes when the agent writes the file. The narrative-regeneration cell uses Pattern A (subprocess) so the full Cadence plugin runtime is in scope.

```python
import marimo
__generated_with = "0.19.7"
app = marimo.App(width="full")

with app.setup:
    import marimo as mo
    import subprocess, json, pathlib, datetime
    ROOT = pathlib.Path(".").resolve()

@app.cell
def header(mo):
    mo.md("# Cadence Console")
    return

@app.cell
def today(mo):
    active = (ROOT / "pursuits" / "_active").read_text().strip() if (ROOT / "pursuits" / "_active").exists() else None
    if active:
        intent = mo.watch.file(ROOT / "pursuits" / active / "intent.md")
        mo.md(f"## Today — {active}\n\n{intent.read_text()}")
    else:
        mo.md("## Today\n\n_no active pursuit — `cadence:start <pursuit>`_")
    return

@app.cell
def validations(mo):
    p = ROOT / "validations" / "pending.md"
    if p.exists() and p.read_text().strip():
        v = mo.watch.file(p)
        mo.md(f"## Pending validations\n\n{v.read_text()}")
    return

@app.cell
def inbox(mo):
    thoughts_dir = mo.watch.directory(ROOT / "thoughts")
    untriaged = [t for t in thoughts_dir.glob("*.md") if "status: untriaged" in t.read_text()]
    if untriaged:
        triage_btn = mo.ui.run_button(label=f"Triage {len(untriaged)} thoughts")
        mo.md(f"## Inbox — {len(untriaged)} untriaged")
        triage_btn
    else:
        triage_btn = None
        mo.md("## Inbox\n\n_empty ✓_")
    return triage_btn,

@app.cell
def brainstorms(mo):
    import yaml
    bdir = mo.watch.directory(ROOT / "brainstorms")
    rows = []
    for b in sorted(bdir.iterdir() if bdir.exists() else []):
        if (b / "meta.yaml").exists():
            meta = yaml.safe_load((b / "meta.yaml").read_text())
            rows.append({"slug": b.name, "phase": meta.get("phase"),
                         "last_touched": meta.get("last_touched")})
    if rows:
        mo.md("## Active brainstorms")
        mo.ui.table(rows)
    return

@app.cell
def narrative(mo):
    p = ROOT / "narratives" / "console" / "summary.cc.md"
    p.parent.mkdir(parents=True, exist_ok=True)
    summary_file = mo.watch.file(p) if p.exists() else None
    regen = mo.ui.run_button(label="Regenerate narrative summary")
    mo.md("## Since last review")
    if summary_file:
        mo.md(summary_file.read_text())
    else:
        mo.md("_click Regenerate_")
    regen
    return regen,

@app.cell
def regen_handler(regen, mo):
    if regen.value:
        with mo.status.spinner("Asking Cadence/Claude Code…"):
            subprocess.run(
                ["claude", "-p",
                 "Use cadence:narrate to refresh narratives/console/summary.cc.md "
                 "with a since-last-review summary of pursuit progress, stalled work, "
                 "and pending triage. Write to that file; do not respond inline.",
                 "--allowedTools", "Read,Edit,Write,Glob,Grep"],
                capture_output=True, text=True, cwd=str(ROOT), timeout=120,
            )
        mo.md(f"_done at {datetime.datetime.now():%H:%M:%S}_")
    return

@app.cell
def quick_capture(mo):
    text = mo.ui.text_area(placeholder="Quick thought…", full_width=True, rows=3)
    submit = mo.ui.run_button(label="Capture")
    mo.md("## Quick capture")
    mo.vstack([text, submit])
    return text, submit

@app.cell
def quick_capture_handler(text, submit, mo):
    if submit.value and text.value.strip():
        subprocess.run(["claude", "-p", f"cadence:capture {text.value!r}",
                        "--allowedTools", "Read,Write"],
                       cwd=str(ROOT), timeout=30)
        mo.md(f"_captured at {datetime.datetime.now():%H:%M:%S}_")
    return

@app.cell
def reflections(mo):
    rdir = ROOT / "reflections"
    if rdir.exists():
        latest = max(rdir.glob("*.md"), key=lambda p: p.stat().st_mtime, default=None)
        if latest:
            f = mo.watch.file(latest)
            mo.md(f"## Most recent reflection — `{latest.name}`\n\n{f.read_text()}")
    return

if __name__ == "__main__":
    app.run()
```

Quick capture writes through `claude -p cadence:capture` rather than touching `thoughts/` directly, so Cadence's frontmatter/ID-generation logic runs in one place. Same principle for the narrative regeneration — every agent-touching cell shells out to `claude -p`.

## Three patterns for "call Claude Code from a Marimo cell"

**Pattern A — `subprocess(["claude", "-p", ...])` (recommended default).** Simple, no Python deps beyond stdlib, identical to Cadence's existing CLI surface. `claude -p` blocks until completion (typically 10–60s); Marimo handles long-running cells fine — the cell shows a spinner; other cells stay interactive. Don't pass `--bare` — Cadence Console needs the plugin's runtime, skills, and CLAUDE.md to load.

**Pattern B — `claude-agent-sdk` (Python) for tighter integration.** Useful if Cadence later wants to expose richer programmatic surfaces (a Marimo cell that exposes a custom in-process MCP tool the agent can call back into during the same query). Overkill for the v1.1 default; keep it on the roadmap.

```python
import anyio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, TextBlock

async def regenerate_narrative():
    options = ClaudeAgentOptions(
        allowed_tools=["Read", "Edit", "Write", "Glob", "Grep"],
        max_turns=10,
        setting_sources=["project"],  # load .claude/ and CLAUDE.md
    )
    async for msg in query(prompt="Use cadence:narrate…", options=options):
        if isinstance(msg, AssistantMessage):
            for block in msg.content:
                if isinstance(block, TextBlock):
                    yield block.text
```

**Pattern C — ACP via the Agent sidebar.** Marimo v0.16+ supports the Agent Client Protocol via an experimental Lab feature flag. User runs `marimo edit --watch console.py`, opens the Agent panel, runs the `claude-code-acp` adapter, and any chat in the sidebar goes through Claude Code with full plugin/skill access. This is the right answer for *"I'm sitting in front of the notebook and want to converse with Claude Code about it,"* but it's experimental (per marimo Newsletter 18) and broken behind reverse proxies (marimo issue #8531). Document as the power-user path; don't depend on it for the v1.1 default.

## Marimo's tooling, as of mid-2026

Confirmed for the design pass:

- **`marimo edit --watch`** streams external edits into the open browser. By default, synced cells are marked stale, not auto-run. To auto-run, set `[tool.marimo.runtime] on_cell_change = "autorun"` in `pyproject.toml`. (`marimo run --watch` forces a full page refresh on file change, resetting UI state — wrong for Cadence Console.)
- **`mo.watch.file` and `mo.watch.directory`** trigger dependent cells when files/directories change. Default polling interval is 1 second; install `watchdog` for OS-event-based watching.
- **WASM/Pyodide doesn't work.** `mo.watch.file` raises `RuntimeError: Unsupported stream type <class 'marimo._pyodide.streams.PyodideStream'>` on marimo.app (issue #7956). Cadence Console must be a local notebook.
- **`marimo check --fix` as a PostToolUse hook.** Bundle with the plugin, gated on the touched file containing `import marimo` and `@app.cell`.
- **Marimo's CLAUDE.md** is the file the marimo team curls into agent prompts (`https://docs.marimo.io/CLAUDE.md`). Key rules: edit only inside `@app.cell` bodies; import all modules in the first cell; never redeclare variables across cells.

## Caveats

- **Marimo's ACP support is experimental** (Newsletter 18: *"this feature is experimental and under active development"*) and gated by a Lab flag. ACP is documentation, not dependency.
- **Marimo MCP support is also experimental.** If Cadence ever wants to surface notebook state to Claude Code via Marimo's MCP server, that's a footnote, not a critical path.
- **Marimo's "Text formatting is preserved" guarantee** is scoped to cell-body contents. Top-level comments and `__generated_with` are regenerated on every save. The Console design avoids relying on this.
- **`marimo run --watch` resets UI state** on every regeneration. Use edit mode, not run mode.
- **Marimo's "Format on save" can rewrite multi-line strings** (issue #6882). Ship with `format_on_save = false` in Console's `pyproject.toml` overrides.
- **Marimo's ACP implementation breaks behind reverse proxies** (issue #8531). Fine for local laptop use; problematic for remote dev environments.
- **SessionStart-hook first-run bug** (anthropics/claude-code issue #10997) only affects GitHub-marketplace-installed plugins. The local `claude --plugin-dir` install is unaffected; document the caveat if/when Cadence ever ships to a marketplace.
- **`claude-code-sdk` is deprecated** as of September 29, 2025. Target `claude-agent-sdk` for any future SDK work.

## What would change this design

- If Marimo ships **stable, non-experimental ACP** AND adds custom MCP server support in their chat panel, revisit Pattern A → Pattern C as default. Marimo would then be a first-class Cadence client.
- If the Console's quick-capture and regenerate buttons feel heavy via subprocess UX, promote Pattern B (`claude-agent-sdk`) to the default.
- If the Marimo team's `marimo-pair` skill (shipped in v0.20.0) matures, it becomes an alternative "agent edits running notebook" path via Marimo's HTTP API. Note that it shifts source-of-truth from disk to the running kernel, which cuts against Cadence's pure-file storage model.
