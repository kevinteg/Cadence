# Cadence v1.1 Architecture Recommendation: Marimo Console, Two-Verb Ingestion, and Convergent Brainstorms

## TL;DR

- **Default to a "notebook references, Claude Code owns sidecars" architecture for Cadence Console.** `console.py` is human-authored and stable; every agent-managed section is a separate `narratives/console/*.cc.md` file rendered via `mo.watch.file(...).read_text()`. Trigger regeneration with `subprocess(["claude", "-p", "cadence:narrate ..."])` from a Marimo button. This sidesteps Marimo's narrow text-preservation guarantees (Marimo's "Text formatting is preserved" promise applies only inside `@app.cell` bodies, not between cells), uses the simplest correct mechanism, and lets ACP/`claude-agent-sdk` (Anthropic's renamed SDK as of September 29, 2025) come in as v1.2 enhancements.
- **Collapse the five ingest paths into `cadence:capture` with `--from <path|url>`, `--source <named>` (named MCP queries defined in `cadence.yaml`), `--prompt`, and `--dump`.** Every ingest dispatches a `capture-ingest` Claude Code subagent for context isolation — per the Anthropic subagent docs, "the verbose output stays in the subagent's context while only the relevant summary returns to your main conversation." Triage stays inside `cadence:reflect`'s Get Clear; no new triage verb.
- **Retire `develop`/`promote` into `brainstorm`-internal mechanics.** A top-level `brainstorms/<slug>/` workspace carries `meta.yaml: phase: diverging|converging|crystallized`, `solutions/<name>.md` per candidate, and a `cadence:brainstorm --crystallize` flag that materializes a pursuit from the selected solution. Extend the SessionStart hook (the validations-queue pattern Kevin already likes) to coach empty repos, surface untriaged thoughts, and list active brainstorms, with explicit suppression rules to avoid pestering.

## What changed since the prior brief

Five corrections from the earlier analysis now that Marimo, Claude Code, and the agent ecosystem have been verified at the source:

1. **Marimo's coding-agent integration is more mature than assumed.** Beyond `--mcp` (server) and `--watch`, Marimo now has (a) an MCP client wired into the chat panel, (b) experimental Agent Client Protocol (ACP) support in the Agent sidebar that connects Claude Code, Gemini CLI, Codex, and OpenCode directly, and (c) an official `marimo-pair` agent skill — the marimo v0.20.0 release notes describe it verbatim as "launches marimo pair — an agent skill that drops AI agents directly inside a running marimo notebook session — along with a cleaner, more responsive data table experience and a slate of reliability fixes." The "can Marimo invoke Claude Code?" question has three working answers as of May 2026, not one.
2. **The marker-comment interleaving pattern is viable on a narrower surface than I'd hoped.** Marimo's "Text formatting is preserved" guarantee applies inside `@app.cell` function bodies; the area between cells is regenerated by codegen and arbitrary top-level comments are not promised to survive a roundtrip (issue #2369 explicitly tracks this as a feature request). Markers must live inside cells, not between them.
3. **The Claude Code SDK has been renamed.** The Python package `claude-code-sdk` was deprecated on September 29, 2025 — its PyPI page now warns verbatim: "⚠️ DEPRECATED: This package has been deprecated and is no longer maintained. Please migrate to the Claude Agent SDK (claude-agent-sdk)." Cadence should target `claude-agent-sdk`, not the old name.
4. **`develop` / `promote` are outside the user's mental model, not just clumsy.** Kevin's instinct to dissolve them into `brainstorm`-internal mechanics is correct and well-supported by GTD's two-step "capture → clarify" prior art and Anthropic's progressive-disclosure skill design.
5. **Claude Code's plugin system has a known SessionStart-hook footgun.** SessionStart hooks loaded from GitHub marketplace plugins silently fail to fire on the *first* run (anthropics/claude-code issue #10997). For a local `claude --plugin-dir ~/code/cadence/cadence-plugin` install this is not a problem; for any future marketplace distribution it is, and the design should not assume SessionStart fires on first invocation.

## Thread 1 — Marimo + Claude Code interleaving (verified)

### 1a. Marimo's AI capabilities, as of May 2026

**`--mcp` server (Marimo as MCP server).** Confirmed and *expanded* since the marimo blog post Kevin cited. The current MCP tool surface, per `docs.marimo.io/guides/editor_features/mcp/` (page dated May 21, 2026) and `docs.marimo.io/guides/editor_features/tools/` (May 14, 2026), is **10 read-only tools exposed via MCP**, plus **2 editing tools available only in the chat panel's Agent mode and explicitly NOT exposed via MCP** ("These tools are only available when using the chat panel in agent mode. They are not exposed through the MCP server."):

| Tool | Surface | Purpose |
|---|---|---|
| `get_active_notebooks` | MCP + Ask | List running notebooks, session IDs, paths |
| `get_lightweight_cell_map` | MCP + Ask | Cell structure preview (id, type, runtime state) |
| `get_cell_runtime_data` | MCP + Ask | Full cell code + runtime metadata + defined vars |
| `get_cell_outputs` | MCP + Ask | Visual output, stdout/stderr per cell |
| `get_cell_dependency_graph` | MCP + Ask | DAG; ownership map; cycles |
| `get_tables_and_variables` | MCP + Ask | In-memory dataframes + variable values |
| `get_database_tables` | MCP + Ask | DB schema with optional regex |
| `get_notebook_errors` | MCP + Ask | Per-cell error summary |
| `lint_notebook` | MCP + Ask | `marimo check` errors over MCP |
| `get_marimo_rules` | MCP + Ask | Returns marimo's CLAUDE.md content |
| `edit_notebook` | **Agent only** | Add/remove/update cells |
| `run_stale_cells` | **Agent only** | Trigger execution |

The blog Kevin cited listed only the original six; the docs add `get_cell_outputs`, `get_cell_dependency_graph`, `get_notebook_errors`, and `lint_notebook`. Wiring is `claude mcp add --transport http marimo http://localhost:PORT/mcp/server` after `marimo edit --mcp` with the `marimo[mcp]` extras.

**Marimo as MCP client.** Confirmed: "marimo can connect to external MCP servers to add additional tools and context to the chat panel." Configured via marimo settings or `marimo.toml`. However, the docs explicitly note: "Support for custom MCP server configuration is not yet available." This matters for Cadence: **Marimo cannot today be configured to point its in-app chat at the Cadence plugin's MCP server**, even if Cadence had one (it doesn't — it's a Claude Code plugin).

**Agent Client Protocol (ACP) — Marimo Newsletter 18 / v0.16.0.** The most important new capability for Kevin's question. Per `marimo.io/blog/newsletter-18`, verbatim: "Bring agents like Claude Code or Gemini into marimo through the new Agent sidebar; once connected, you can boss your agent around in the editor, which in turn will be able to make edits to your notebook. This experimental integration uses the Agent Client Protocol (ACP) to enable AI agents to help write and modify code directly in your notebooks. Note: this feature is experimental and under active development." Connection command per `docs.marimo.io/guides/editor_features/agents/`:

```
npx stdio-to-ws "npx @zed-industries/claude-code-acp" --port 3017
```

Once connected, **the running Claude Code agent can read and write cells in the open marimo notebook directly through ACP**. This inverts Kevin's framing: the notebook never has to shell out itself; the user clicks "Pair with Agent" and the agent edits cells through ACP.

**`marimo edit --watch`.** When the .py file is changed externally (by Claude Code's Edit tool), marimo streams the diff into the open browser. By default *synced cells are marked stale, not auto-run*. To auto-run, set in `pyproject.toml`:

```toml
[tool.marimo.runtime]
auto_instantiate = true
on_cell_change = "autorun"
```

`marimo run --watch` (app mode) behaves differently — on file change, it forces a full browser page refresh that **resets all UI state**. Edit mode is the right choice for Cadence Console; run mode loses state on every regeneration.

**`mo.watch.file` / `mo.watch.directory`.** `mo.watch.file(path)` returns a reactive wrapper that triggers dependent cells when the file's *contents* change; `mo.watch.directory(path)` triggers when the directory's *structure* changes. Default polling interval is 1.0 second per `marimo/_runtime/watch/_path.py:33`; install `watchdog` for OS-event-based watching. **Important caveat:** `mo.watch.file` does not work in WASM/Pyodide notebooks — issue #7956 reports the verbatim error: "RuntimeError: Unsupported stream type `<class 'marimo._pyodide.streams.PyodideStream'>`" (against marimo 0.19.4 on marimo.app). Cadence Console must be a local notebook, not a WASM-deployed one.

**Marimo's CLAUDE.md (`docs.marimo.io/CLAUDE.md`).** This is the file the marimo team curls into agent prompts (`curl https://docs.marimo.io/CLAUDE.md > ~/.claude/prompts/marimo.md`). Verbatim key rules:

> "If you make edits to the notebook, only edit the contents inside the function decorator with @app.cell. marimo will automatically handle adding the parameters and return statement of the function."

> "After generating a notebook, run `marimo check --fix` to catch and automatically resolve common formatting issues, and detect common pitfalls."

> "Import all modules in the first cell, always including `import marimo as mo`" / "Never redeclare variables across cells" / "Don't include comments in markdown cells" / "Don't include comments in SQL cells"

Cell template (verbatim):

```python
@app.cell
def _():
    <your code here>
    return
```

### 1b. Calling Claude Code from a Marimo notebook

Three legitimate patterns, ordered for Cadence:

**Pattern A — Subprocess to `claude -p` (recommended default).** Simple, no Python deps beyond stdlib, identical to Cadence's existing CLI surface. From `code.claude.com/docs/en/headless`:

> "To run Claude Code in non-interactive mode, pass -p with your prompt and any CLI options: `claude -p "Find and fix the bug in auth.py" --allowedTools "Read,Edit,Bash"`"

> "Add `--bare` to reduce startup time by skipping auto-discovery of hooks, skills, plugins, MCP servers, auto memory, and CLAUDE.md."

For Cadence-from-Marimo you do **not** want `--bare` — you want the plugin's runtime, skills, and CLAUDE.md to load. Concrete pattern:

```python
@app.cell
def regen_button(mo):
    regen = mo.ui.run_button(label="Regenerate narrative")
    regen
    return regen,

@app.cell
def regen_handler(regen, mo):
    import subprocess, pathlib
    if regen.value:
        with mo.status.spinner("Asking Cadence/Claude Code…"):
            subprocess.run(
                ["claude", "-p",
                 "Use cadence:narrate to refresh narratives/console/summary.cc.md "
                 "summarizing pursuits/, validations/pending.md, and thoughts/ since the last reflection.",
                 "--allowedTools", "Read,Edit,Write,Glob,Grep"],
                capture_output=True, text=True,
                cwd=str(pathlib.Path.cwd()), timeout=120,
            )
    return

@app.cell
def render(mo):
    summary = mo.watch.file("narratives/console/summary.cc.md")
    mo.md(summary.read_text() if summary.exists() else "_no narrative yet — click Regenerate_")
    return
```

Streaming: `claude -p` blocks until completion (typically 10–60s). Marimo handles long-running cells fine — the cell shows a spinner; other cells stay interactive. Use `--output-format stream-json` with `subprocess.Popen` later if you want progress, but the blocking pattern above is enough for v1.1.

**Pattern B — `claude-agent-sdk` (Python) for tighter integration.** Per `github.com/anthropics/claude-agent-sdk-python`:

```python
import anyio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, TextBlock

async def regenerate_narrative():
    options = ClaudeAgentOptions(
        allowed_tools=["Read", "Edit", "Write", "Glob", "Grep"],
        max_turns=10,
        setting_sources=["project"],  # load .claude/ and CLAUDE.md
    )
    async for msg in query(prompt="Use cadence:narrate…", options=options):
        if isinstance(msg, AssistantMessage):
            for block in msg.content:
                if isinstance(block, TextBlock):
                    yield block.text
```

Useful if Cadence later wants to expose richer programmatic surfaces (a Marimo cell that exposes a custom in-process MCP tool the agent can call back into during the same query). For v1.1, overkill — keep it on the v1.2 roadmap.

**Pattern C — ACP via the Agent sidebar.** Confirmed working in marimo v0.16+. User runs `marimo edit --watch console.py`, enables the Lab feature flag, opens the Agent panel, runs the `claude-code-acp` adapter, and any chat in the sidebar goes through Claude Code with full plugin/skill access. **Recommendation: document this as the "drive Cadence from inside the running notebook" path for power users; do not depend on it for the v1.1 default flow** — Marimo's docs explicitly call it experimental, and issue #8531 reports it's "broken in common remote deployment scenarios where marimo is accessed through a reverse proxy, TLB, or cloud IDE workspace proxy" because "the current Agent Panel (ACP) implementation connects directly from the browser to the agent WebSocket server (e.g., ws://`<hostname>`:3017/message)."

### 1c. The interleaving pattern: where can Claude Code write inside a Marimo notebook?

The part where I was over-optimistic in the prior brief. Verified roundtrip behavior:

| Where you put a marker | Survives `marimo edit --watch` save? |
|---|---|
| Comments INSIDE an `@app.cell` body | **Yes** — "Text formatting is preserved" guarantee in marimo's fileformat tutorial covers whitespace, line breaks, and comments inside cell bodies |
| Comments OUTSIDE any cell (between `@app.cell` decorators) | **No guarantee** — codegen regenerates the structural template (lint rule MF001 enforces "correct file generation metadata"); issue #2369 confirms this is still a feature request, not current behavior |
| Multi-line string literals (e.g., inside `mo.md("""…""")`) | **Yes** — covered by the same guarantee; *but* turn off "Format on save" or SQL/markdown contents may get reflowed (issue #6882) |
| `__generated_with` version string at the top | **Overwritten on every save** |

**Implication for the marker pattern.** Kevin's preferred option (c) — interleaved live editing with `<!-- CC:generated start -->` markers — works, **but the markers must live inside `@app.cell` bodies, not between them**. Concretely:

```python
@app.cell
def _cc_generated_narrative(mo):
    # CC:generated start id=narrative
    mo.md(open("narratives/console.cc.md").read())
    # CC:generated end id=narrative
    return
```

That marker survives roundtrip. But this:

```python
# CC:generated start id=narrative  <-- LOST on next save
@app.cell
def _():
    ...
# CC:generated end id=narrative     <-- LOST
```

…gets regenerated away.

**Recommendation (Architecture Decision A1):** **"Notebook references, Claude Code owns sidecars."** Cadence Console's `console.py` is human-authored and short. Each agent-managed section is its own markdown file under `narratives/console/<section>.cc.md`. Each section is rendered by a small Marimo cell that does `mo.md(mo.watch.file("narratives/console/today.cc.md").read_text())`. Claude Code only ever writes to the `.cc.md` files, never to `console.py`. The Marimo cell auto-refreshes when the file changes.

This gives you everything (c) was supposed to give you — interleaved sections, agent-managed regions, live regen — without ever asking Claude Code to thread an Edit through a `.py` file whose format guarantees are scoped to cell bodies. It's also the pattern Eric Ma reaches for in `ericmjl.github.io/blog/2025/10/28/use-coding-agents-to-write-marimo-notebooks` as the "let the agent write Python; let the notebook render results" mental model.

The only thing you give up vs. true inline interleaving: you can't have CC-generated *Python code* inside the notebook unless you let Claude Code edit `console.py` directly. For Cadence Console that's the right tradeoff — the Python is plumbing; the value lives in the .cc.md content.

### 1d. Cell ID stability and the `marimo check` self-correction loop

Two practical observations from Eric Ma's piece and the marimo-team/skills repo:

1. Cell IDs are not stable across Claude Code edits — Marimo regenerates them from function names. If you give cells stable function names (`@app.cell\ndef quick_capture(mo):`), the function name *is* your stable identifier. **Recommendation: every cell in `console.py` gets a named function.**

2. `marimo check` should run as a PostToolUse hook on the plugin. The marimo team's recommended hook (from `docs.marimo.io/guides/generate_with_ai/using_claude_code/`):

```json
{ "hooks": { "PostToolUse": [ { "matcher": "Edit|Write",
  "hooks": [ { "type": "command",
    "command": "${CLAUDE_PLUGIN_ROOT}/hooks/marimo-check.sh" } ] } ] } }
```

Cadence v1.1 should ship this hook with a guard that only runs `uvx marimo check` when the file contains `import marimo` and `@app.cell`.

## Thread 2 — Two-verb ingestion + convergent brainstorm cleanup

### 2a. Prior art that informs the design

GTD's **capture → clarify** is the cleanest direct analog. From the Todoist GTD guide: "Capture tasks and ideas: Capture anything that crosses your mind… These items go directly into your inboxes. Clarify actions: Process what you've captured into clear and concrete action steps. Decide if an item is a project, next action, or reference." And Wikipedia on GTD: "Do not put clarified items back into the inbox."

Two GTD-derived rules to bake into Cadence:

- **The two-minute rule** — if the captured item can be resolved in under two minutes ("obvious action item, add to active pursuit"), `capture` should offer to do it inline instead of routing to `thoughts/`.
- **Inboxes get emptied, not browsed.** A `thoughts/` inbox that grows monotonically is a failure mode. The reconciler's Get Clear should explicitly prompt to triage rather than just listing count.

PARA / Building a Second Brain (Tiago Forte) is a weaker fit — its "Resources / Areas / Projects / Archives" taxonomy is for *reference material*, not actionable work, and Cadence's `pursuits / thoughts / reflections / narratives` already covers the actionable side. Skip PARA's CODE framework for v1.1.

Anthropic's **Agent Skills progressive-disclosure model** is the right abstraction for how Cadence's verbs internally route between paths. Per Anthropic's "Equipping agents for the real world with Agent Skills": SKILL.md frontmatter is metadata-only and "provides just enough information for Claude to know when each skill should be used without loading all of it into context"; SKILL.md body loads on activation; bundled references load only when the agent navigates to them. For `capture`, this means: one SKILL.md frontmatter description, one core body, and per-path reference files for the five distinct ingest modalities — Claude Code's tool selector decides which to load.

### 2b. `cadence:capture` — proposed surface

Kevin's `--from` overloading approach is correct with two refinements (named MCP sources via config, explicit `--dump` for editor-driven brain dumps). Final surface:

```
cadence:capture                          # blank thought entry — opens editor (existing behavior)
cadence:capture "<text>"                 # one-shot quick thought
cadence:capture --                       # read from stdin (pipe-friendly)
cadence:capture --from <path-or-url>     # ingest a document
cadence:capture --from <path-or-url> --prompt "<filtering instructions>"
cadence:capture --source <named-source>  # MCP-query-driven ingest (configured in cadence.yaml)
cadence:capture --dump                   # open $EDITOR for long-form brain dump
```

**Frontmatter schema for `thoughts/<id>.md`** (ready for SKILL.md):

```yaml
---
id: 2026-05-22-1547-glean-onboarding
captured_at: 2026-05-22T15:47:00-07:00
source:
  kind: mcp           # one of: inline | stdin | file | url | mcp | dump
  name: onboarding    # named source from cadence.yaml, when kind == mcp
  server: glean       # MCP server id
  query: "onboarding docs from last 30 days"
  fetched_via: subagent  # bump-in-the-wire principle: raw payload isolated
raw_path: thoughts/_raw/2026-05-22-1547-glean-onboarding.raw.md
distilled_path: thoughts/2026-05-22-1547-glean-onboarding.md
prompt: "Pull action items relevant to my first 30 days"
status: untriaged     # untriaged | triaged | promoted | discarded
triaged_to: null      # later: { pursuit: "nexthop-onboarding", action_ids: [...] }
two_minute_eligible: false
tags: [onboarding, nexthop]
---
```

**Named MCP sources in `cadence.yaml`** (resolves "is `mcp://server/query` the right URI?" — no, it's brittle; use named sources):

```yaml
ingest_sources:
  onboarding:
    server: glean
    query: "onboarding docs from last 30 days OR shared with me by hiring manager"
    summarize_with: "Pull action items I should own in my first 30 days."
  jira_inbox:
    server: jira
    jql: "assignee = currentUser() AND status = 'To Do'"
  cadence_issues:
    server: github
    query: "repo:kevinteg/cadence is:issue is:open label:capture-source"
```

Invocation becomes `cadence:capture --source onboarding` — more ergonomic than `mcp://glean/?q=...`, and lets the user iterate on prompts/queries in version control.

**Sub-agent isolation (the "bump in the wire" principle).** Strongly supported by Claude Code's subagent system per `code.claude.com/docs/en/sub-agents`:

> "Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions. … the verbose output stays in the subagent's context while only the relevant summary returns to your main conversation."

For Cadence: every `--from` and `--source` invocation dispatches a Cadence-specific `capture-ingest` subagent (`cadence-plugin/agents/capture-ingest.md`) with restricted tools (just the relevant MCP server + Write) that pulls the raw content, writes it to `thoughts/_raw/<id>.raw.md`, summarizes per the `--prompt`, writes `thoughts/<id>.md`, and returns only `{id, title, two_minute_eligible, suggested_pursuit}` to the main session. The raw payload never bloats Cadence's runtime context.

**Triage trigger — no new verb.** Three existing channels:

1. **SessionStart hook** prints "N untriaged thoughts" above the prompt (extending the existing validations queue pattern).
2. **`cadence:status`** lists them with a coaching prompt.
3. **`cadence:reflect`'s Get Clear** explicitly walks the untriaged set, applying GTD clarify questions ("actionable? two-minute? part of an existing pursuit? new brainstorm? someday?"). The reconciler already runs during /reflect Get Clear — extend it to enumerate `thoughts/*.md` where `status: untriaged`.

This keeps the verb count at 12 and pushes the workflow through patterns Kevin already has.

### 2c. `cadence:brainstorm` and the develop/promote dissolution

Kevin's instinct is right. Cleanest formulation:

**Surface:**

```
cadence:brainstorm <topic>          # start or resume a workspace at brainstorms/<slug>/
cadence:brainstorm                  # list active brainstorms, offer to open one
cadence:brainstorm --crystallize    # in a converging brainstorm: promote selected solution to pursuit
cadence:brainstorm --archive        # close out (move to narratives/ or delete)
```

No flag for "split into solutions" — that's interaction within the session, not a verb argument.

**Directory layout:**

```
brainstorms/
  <slug>/
    workspace.md              # main scratch / divergent notes
    meta.yaml                 # phase, created_at, last_touched, source_thoughts
    refs/
      <id>.md                 # symlinks or copies of pulled-in thoughts
    solutions/
      <name>.md               # one candidate solution per file
    decision.md               # populated on --crystallize
```

Top-level `brainstorms/` directory (matching the existing flat top-level pattern of `pursuits/`, `thoughts/`, `reflections/`) rather than nested under `thoughts/` or `pursuits/`. Brainstorms are first-class WIP workspaces and visibility matters.

**`meta.yaml` schema:**

```yaml
slug: cadence-v2-storage
created_at: 2026-05-22T16:00:00-07:00
last_touched: 2026-05-22T17:30:00-07:00
phase: converging         # diverging | converging | crystallized | archived
source_thoughts: [2026-05-19-1130-storage-frustration]
candidate_solutions: [sqlite-migration, yaml-index, content-addressable]
selected_solution: null   # populated on crystallize
target_pursuit: null
```

**Phase mechanic (no new verb).** Inside a `cadence:brainstorm` session, the runtime coaches the user through diverging → converging. When the user says "I have three candidate solutions," Cadence/Claude Code creates `solutions/<name>.md` files (just file ops, no verb), updates `meta.yaml: phase: converging`, and the brainstorm-workspace skill instructs the agent to treat each solution as an artifact to iterate on. When the user picks one, `--crystallize` materializes the pursuit:

```
pursuits/<new-pursuit>/
  intent.md            # populated from solutions/<selected>.md preamble
  actions.md           # populated from solutions/<selected>.md's "Next steps" section
  context.md           # links back to brainstorms/<slug>/
brainstorms/<slug>/decision.md   # records what was chosen and why
```

`meta.yaml: phase: crystallized, target_pursuit: <new-pursuit>`. The brainstorm folder stays in place as a `narratives/`-eligible artifact. `--archive` is a separate, explicit step (moves to `narratives/brainstorms/<slug>/` or deletes per user choice).

**Initial actions from a selected solution.** Convention: each `solutions/<name>.md` is structured with a `## Next steps` H2 that lists `- [ ] action` lines. `--crystallize` parses those into `pursuits/<new>/actions.md`. The SKILL.md should enforce this on creation.

**Status visibility.** Yes — `cadence:status` surfaces active brainstorms with last-touched timestamps and phase. Makes them feel like real trackable WIP, not "scratch I'll lose."

### 2d. Coaching surface — SessionStart hook + verb-level coaching

The existing `validations/pending.md`-above-the-prompt pattern is the right shape; extend it. Proposed SessionStart hook output:

```
🎵 Cadence
─────────────────────────────────────
Active pursuit: nexthop-onboarding (started 3d ago)
Pending validations: 2  →  resolve with `cadence:resolve`
Untriaged thoughts: 4   →  triage in `cadence:reflect` Get Clear
Active brainstorms: 1   (cadence-v2-storage, last touched 4h ago, converging)
Last session: 4h ago
─────────────────────────────────────
```

**Empty-repo coaching** (no pursuits, no thoughts, no brainstorms):

```
🎵 Cadence is initialized but empty.

What do you want to accomplish?
  • Quick thought    →  cadence:capture "..."
  • Long brain dump  →  cadence:capture --dump
  • Ingest a doc     →  cadence:capture --from <path>
  • Start exploring  →  cadence:brainstorm <topic>
  • Initialize state →  cadence:init
```

**Verb-level coaching (mechanism).** Each SKILL.md has an explicit "if-empty" branch. Example `cadence-plugin/skills/status/SKILL.md`:

```markdown
## When invoked

1. Read `pursuits/`, `thoughts/`, `brainstorms/`, `validations/pending.md`.
2. If all are empty, output the coaching block (see references/empty-coaching.md).
3. If only `thoughts/` has untriaged entries, lead with the triage nudge.
4. Otherwise, render the standard status dashboard.
```

This follows Anthropic's progressive-disclosure pattern: SKILL.md stays lean; the empty-state coaching template lives in `references/empty-coaching.md` and only loads when relevant.

**Frequent summarization — avoid pestering.** Suppress the SessionStart block when:

- A `.cadence/last_session_block.json` was emitted < 60 minutes ago AND no state has changed (no new pursuits, no new validations, no new thoughts).
- The user dismissed the block in the previous session (write a `.cadence/dismissed_at` timestamp; suppress for 24h).

For end-of-session summarization, use the **Stop** hook (fires when Claude Code finishes a turn naturally) to append a one-line entry to `narratives/session-log.md` if the session had material activity. Don't use SubagentStop — too chatty. Don't use PreCompact — the user has already lost the thread by then.

## Thread 3 — Cadence Console: the Marimo notebook

### 3a. Concrete notebook layout

`cadence-plugin/views/console.py` lives in the plugin, versioned with it, copied to the user's repo on `cadence:init` so they can customize per-repo without losing updates. Every cell named:

```python
import marimo
__generated_with = "0.19.7"
app = marimo.App(width="full")

with app.setup:
    import marimo as mo
    import subprocess, json, pathlib, datetime
    ROOT = pathlib.Path(".").resolve()

@app.cell
def header(mo):
    mo.md("# 🎵 Cadence Console")
    return

@app.cell
def today(mo):
    active = (ROOT / "pursuits" / "_active").read_text().strip() if (ROOT / "pursuits" / "_active").exists() else None
    if active:
        intent = mo.watch.file(ROOT / "pursuits" / active / "intent.md")
        mo.md(f"## Today — {active}\n\n{intent.read_text()}")
    else:
        mo.md("## Today\n\n_no active pursuit — `cadence:start <pursuit>`_")
    return

@app.cell
def validations(mo):
    p = ROOT / "validations" / "pending.md"
    if p.exists() and p.read_text().strip():
        v = mo.watch.file(p)
        mo.md(f"## Pending validations\n\n{v.read_text()}")
    return

@app.cell
def inbox(mo):
    thoughts_dir = mo.watch.directory(ROOT / "thoughts")
    untriaged = [t for t in thoughts_dir.glob("*.md")
                 if "status: untriaged" in t.read_text()]
    if untriaged:
        triage_btn = mo.ui.run_button(label=f"Triage {len(untriaged)} thoughts")
        mo.md(f"## Inbox — {len(untriaged)} untriaged")
        triage_btn
    else:
        triage_btn = None
        mo.md("## Inbox\n\n_empty ✓_")
    return triage_btn,

@app.cell
def brainstorms(mo):
    import yaml
    bdir = mo.watch.directory(ROOT / "brainstorms")
    rows = []
    for b in sorted(bdir.iterdir() if bdir.exists() else []):
        if (b / "meta.yaml").exists():
            meta = yaml.safe_load((b / "meta.yaml").read_text())
            rows.append({"slug": b.name, "phase": meta.get("phase"),
                         "last_touched": meta.get("last_touched")})
    if rows:
        mo.md("## Active brainstorms")
        mo.ui.table(rows)
    return

@app.cell
def narrative(mo):
    p = ROOT / "narratives" / "console" / "summary.cc.md"
    p.parent.mkdir(parents=True, exist_ok=True)
    summary_file = mo.watch.file(p) if p.exists() else None
    regen = mo.ui.run_button(label="Regenerate narrative summary")
    mo.md("## Since last review")
    if summary_file:
        mo.md(summary_file.read_text())
    else:
        mo.md("_click Regenerate_")
    regen
    return regen,

@app.cell
def regen_handler(regen, mo):
    if regen.value:
        with mo.status.spinner("Asking Cadence/Claude Code…"):
            subprocess.run(
                ["claude", "-p",
                 "Use cadence:narrate to refresh narratives/console/summary.cc.md "
                 "with a since-last-review summary of pursuit progress, stalled work, "
                 "and pending triage. Write to that file; do not respond inline.",
                 "--allowedTools", "Read,Edit,Write,Glob,Grep"],
                capture_output=True, text=True, cwd=str(ROOT), timeout=120,
            )
        mo.md(f"_done at {datetime.datetime.now():%H:%M:%S}_")
    return

@app.cell
def quick_capture(mo):
    text = mo.ui.text_area(placeholder="Quick thought…", full_width=True, rows=3)
    submit = mo.ui.run_button(label="Capture")
    mo.md("## Quick capture")
    mo.vstack([text, submit])
    return text, submit

@app.cell
def quick_capture_handler(text, submit, mo):
    if submit.value and text.value.strip():
        subprocess.run(["claude", "-p", f"cadence:capture {text.value!r}",
                        "--allowedTools", "Read,Write"],
                       cwd=str(ROOT), timeout=30)
        mo.md(f"_captured at {datetime.datetime.now():%H:%M:%S}_")
    return

@app.cell
def reflections(mo):
    rdir = ROOT / "reflections"
    if rdir.exists():
        latest = max(rdir.glob("*.md"), key=lambda p: p.stat().st_mtime, default=None)
        if latest:
            f = mo.watch.file(latest)
            mo.md(f"## Most recent reflection — `{latest.name}`\n\n{f.read_text()}")
    return

if __name__ == "__main__":
    app.run()
```

Key decisions baked in:

- Every cell has a stable function name (survives Claude Code edits cleanly).
- Markdown content is rendered via `mo.watch.file(path).read_text()` — auto-refreshes when Cadence/Claude Code writes the file.
- The narrative section uses Pattern A (subprocess to `claude -p`) — simplest, no async, full plugin access.
- Quick capture writes through `claude -p cadence:capture` rather than touching `thoughts/` directly, so all Cadence's frontmatter/ID-generation logic runs in one place.
- No CC marker comments in the .py file. Agent-managed content lives entirely in `narratives/console/*.cc.md`.

### 3b. The narrative regeneration mechanism

**Recommended (v1.1):** subprocess to `claude -p` with the `cadence:narrate` skill, writing to `narratives/console/summary.cc.md`, with `mo.watch.file` re-rendering. Simplest correct mechanism; keeps all intelligence in the Cadence plugin runtime (Pattern A explicitly does NOT use `--bare`).

**Not recommended:** direct Anthropic API call from a Marimo cell. Bypasses Cadence's runtime/skills and would diverge prompt behavior from the rest of Cadence. Use the SDK (Pattern B) only if v1.2 needs custom in-process MCP tools — and even then, prefer the SDK with `setting_sources=["project"]` so it still loads the project's `.claude/` config.

**ACP (Pattern C)** is the right answer for "I'm sitting in front of my Marimo notebook and want to converse with Claude Code about it." Document it as the power-user path, not the default plumbing.

### 3c. Where the notebook lives, how it stays in sync

- **Master copy:** `cadence-plugin/views/console.py` in the plugin repo. Versioned with the plugin.
- **Per-repo install:** `cadence:init` copies it to `<repo>/.cadence/views/console.py` (new directory — keeps `pursuits/`, `thoughts/`, etc. clean of plumbing). Users can edit the local copy; future plugin updates do NOT overwrite it. A `cadence:init --update-console` flag re-copies if requested.
- **Launch:** add a `cadence:console` slash command that runs `marimo edit --watch .cadence/views/console.py` (project-scoped command in `cadence-plugin/commands/console.md`).
- **Schema sync:** if Cadence's data model evolves, version the schema in `cadence-plugin/cadence-reference.md` and have `cadence:init` detect schema drift via a `.cadence/schema_version` file. v1.1 is the bootstrap; v1.2 introduces drift detection.

### 3d. Phasing

**v1.1 (ship in 4–6 weeks, before Nexthop start):**

1. Two-verb ingestion: `cadence:capture` with `--from`, `--source` (named MCP sources via `cadence.yaml`), `--dump`, `--prompt`; existing blank/quick behaviors preserved.
2. `capture-ingest` subagent (`cadence-plugin/agents/capture-ingest.md`) with bump-in-the-wire isolation.
3. `brainstorm` workspace mechanic with `--crystallize`, `--archive`, the `brainstorms/` top-level directory, `meta.yaml`, `solutions/`, `decision.md`.
4. Retire `develop` and `promote`; migration: any existing internal callers move to brainstorm-internal file ops.
5. Coaching extensions to SessionStart hook (empty-repo block, untriaged-thoughts block, idle-time prompt) with the 60-minute/dismiss-24h suppression rules.
6. `cadence:narrate` skill that writes to `narratives/<context>/*.cc.md`.
7. `cadence-plugin/views/console.py` Marimo notebook + `cadence:console` slash command + `cadence:init --update-console`.
8. `marimo-check` PostToolUse hook bundled with the plugin (only active when a `.py` notebook is touched).

**v1.2 (defer):**

1. `claude-agent-sdk` Python integration for in-cell Cadence calls (Pattern B), if Pattern A subprocess UX feels heavy.
2. ACP Agent-sidebar documentation page (Pattern C) once Marimo's ACP support exits Lab/experimental.
3. Schema drift detection / Console auto-migration.
4. Per-user MCP source secrets management (today the user manually configures MCP servers in their Claude Code config; v1.2 could wrap that).
5. SQLite materialized view (if pure-markdown query performance becomes a bottleneck — defer until you feel it).

## Recommendations (BLUF reprise)

1. **Adopt the "notebook references, Claude Code owns sidecars" pattern** for Cadence Console (architecture decision A1). Don't put CC-managed marker comments inside `console.py`. Put generated content in `narratives/console/*.cc.md` and render via `mo.watch.file`.
2. **Default to `subprocess(["claude", "-p", ...])` (Pattern A)** for Cadence-from-Marimo. SDK (Pattern B) and ACP (Pattern C) are v1.2 and power-user paths.
3. **Collapse ingestion to `capture` + `brainstorm`** with `--from`, `--source` (named in `cadence.yaml`), and `--dump`. Dispatch every ingest path through a `capture-ingest` subagent for context isolation.
4. **Retire `develop`/`promote`. `brainstorm` owns its phase machine** via `meta.yaml: phase: diverging|converging|crystallized` and a `--crystallize` flag that materializes the pursuit from a selected solution file. Top-level `brainstorms/` directory.
5. **Extend the SessionStart hook** to show validations + untriaged thoughts + active brainstorms + idle-time prompt, with explicit suppression rules (60min unchanged, 24h after dismiss). Coach empty repos with a clear menu of next steps.
6. **Bundle the `marimo-check` PostToolUse hook** so any `.py` notebook edits self-correct.

**Benchmarks that would change these recommendations:**

- If Marimo ships stable, non-experimental ACP support AND adds custom MCP server support in their chat panel, **revisit Pattern A → Pattern C** as default (Marimo would then be a first-class Cadence client).
- If the `thoughts/` triage step ever feels like a separate verb in practice (users keep asking "how do I process my inbox?"), promote a `cadence:triage` thin verb. The default plan keeps it in `reflect`'s Get Clear.
- If `brainstorms/` workspaces start accumulating without crystallizing, that's a signal the converging phase needs more coaching, not a new verb.
- If pure-markdown queries become slow (> ~200ms for `cadence:status`), introduce a derived SQLite index — but don't pre-build it.

## Caveats

- **Marimo's ACP support is explicitly experimental** — Newsletter 18 states verbatim "this feature is experimental and under active development" — and gated by a Lab feature flag. Treat ACP as a documentation note, not a dependency.
- **Marimo MCP support is also marked experimental** in the same docs. Keep it as a "Cadence Console can optionally surface notebook state to Claude Code via Marimo's MCP server" footnote, not a critical path.
- **SessionStart hook first-run bug** (anthropics/claude-code issue #10997) — only affects GitHub-marketplace-installed plugins. Cadence's `claude --plugin-dir` local install is unaffected. Document this if/when Cadence ever publishes to a marketplace.
- **Marimo's "Text formatting is preserved" guarantee** is scoped to cell-body contents (verified in `marimo/_tutorials/fileformat.py`); top-level comments and the `__generated_with` line are regenerated on every save. The Console design avoids relying on this, but any future cell-body marker logic must.
- **`mo.watch.file` does not work in WASM/Pyodide notebooks** (issue #7956 reports the runtime error verbatim: "RuntimeError: Unsupported stream type `<class 'marimo._pyodide.streams.PyodideStream'>`"). Cadence Console must run as a local notebook, not deployed to WebAssembly.
- **Marimo's "Format on save" can rewrite multi-line strings** in some cells (issue #6882). Cadence Console should ship with `format_on_save = false` in its `pyproject.toml` overrides.
- **`claude-code-sdk` is deprecated as of September 29, 2025** — PyPI shows verbatim "⚠️ DEPRECATED: This package has been deprecated and is no longer maintained. Please migrate to the Claude Agent SDK (claude-agent-sdk)." Target `claude-agent-sdk` for any future SDK work.
- **`mo.watch.file` polls at 1.0 second by default** (`marimo/_runtime/watch/_path.py:33`). Install `watchdog` for OS-event watching. Bundle this as a Cadence Console dependency note.
- **Marimo's ACP implementation is broken behind reverse proxies** per issue #8531 verbatim: "The current Agent Panel (ACP) implementation connects directly from the browser to the agent WebSocket server (e.g., ws://`<hostname>`:3017/message). This breaks in common remote deployment scenarios where marimo is accessed through a reverse proxy, TLB, or cloud IDE workspace proxy." Fine for local laptop use; problematic if Kevin ever wants Console behind a remote dev environment proxy.
- **The Marimo team's `marimo-pair` skill exists and is shipped** — per the marimo v0.20.0 release notes verbatim: "This release launches marimo pair — an agent skill that drops AI agents directly inside a running marimo notebook session — along with a cleaner, more responsive data table experience and a slate of reliability fixes." It's an alternative path to "agent edits running notebook" via Marimo's HTTP API rather than file edits. Worth experimenting with after v1.1 ships, but it shifts source-of-truth from disk to the running kernel, which conflicts with Cadence's pure-file storage model.
